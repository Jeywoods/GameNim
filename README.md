# Nim

Консольная игра «Ним» на Swift. Оформлена как Swift Package (executable), использует только Foundation, без внешних зависимостей.

## Требования

- Swift 5.9 или новее
- macOS

## Запуск

```bash
cd Nim
swift run
```

Сборка без запуска:

```bash
swift build
```

## Правила

- Есть несколько кучек камней (от 3 до 10, количество выбирает пользователь).
- Размер каждой кучки задаётся случайно от 3 до 7 камней.
- Камни отображаются точками: кучка из 3 камней выглядит как `● ● ●`.
- Игроки ходят по очереди.
- За один ход игрок берёт любое количество камней (от 1 до всей кучки), но только из одной кучки.
- Кто забрал последний камень, тот побеждает. Ничьих не бывает.

## Режимы игры

1. Игра на двоих: программа спрашивает имена обоих игроков.
2. Игра против компьютера: программа спрашивает имя игрока, второй участник называется «Компьютер». Компьютер выбирает случайную непустую кучку и случайное количество камней от 1 до размера этой кучки.

## Как играть

Перед каждым ходом выводится состояние кучек и имя игрока, чей сейчас ход:

```
Кучка 1: ● ● ●         (3)
Кучка 2: ● ● ● ●       (4)
Кучка 3: ● ● ● ● ●     (5)

Ход: Аня
Номер кучки: 3
Сколько камней взять (от 1 до 5): 2
Аня берёт 2 камня из кучки 3. Осталось: 3, 4, 3
```

Ввод проверяется: при ошибке выводится сообщение, и программа просит ввести значение заново. Если закончился поток ввода (например, Ctrl+D), программа завершается.

## Архитектура

| Слой | Файлы | Назначение |
| --- | --- | --- |
| Модели | `Pile`, `Player`, `Move` | Кучка камней, игрок (имя и стратегия хода), ход (номер кучки и количество камней) |
| Игра | `GameState`, `Game` | `GameState` хранит кучки, игроков и очередь хода, проверяет и применяет ходы. `Game` запускает игровой цикл и определяет победителя |
| Стратегии | `MoveStrategy`, `HumanStrategy`, `RandomComputerStrategy` | Протокол `MoveStrategy` с методом `chooseMove(in:) -> Move`. Человек вводит ход через `InputProvider`, компьютер выбирает случайный |
| Терминал | `InputProvider`, `OutputRenderer`, `ConsoleInput`, `ConsoleOutput` | Протоколы ввода и вывода и их консольные реализации |

Ключевые решения:

- `Game` и стратегии не вызывают `print` и `readLine` напрямую. Весь ввод и вывод идёт через протоколы `InputProvider` и `OutputRenderer`, поэтому консоль можно заменить другой реализацией, не трогая логику игры.
- Игрок хранит стратегию хода, поэтому `Game` не знает, человек перед ним или компьютер.
- `Game` дополнительно проверяет каждый ход через `GameState.isValid`.
- Модификаторы доступа указаны явно.
- Код не содержит комментариев.

## Чего в проекте нет

Сознательно не реализованы: оптимальная стратегия компьютера (XOR), графический интерфейс, сохранение игры, счёт по матчам и уровни сложности.
